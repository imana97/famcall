MUTE DURING CONNECTION SETUP — FIXED AND CHECKED
Previously, mute changed only an existing microphone track. A request made while
credentials, permission or capture were pending could leave the eventual track
enabled even while the UI showed Unmute. VoicePeer now keeps the latest mute
intent and applies it before attaching microphone tracks. Calling passes the
current mute state into a newly created peer and ignores mute events whose native
session ID does not match the active call. The late-event guard is source-checked;
it has not been exercised with a real delayed OS event.

The Android standalone build passed a two-call Maestro check on API 36 emulators:
mute while ringing; remain muted after answer; unmute; remute; hang up while
muted; then make a new unmuted call. All seven phases matched Android's API and
cached system microphone-mute states. The first reported JavaScript microphone
track was disabled in the muted call and enabled in the following call. Both
phones returned to contacts and system mute cleared after teardown.

MEASUREMENT RULES
The audio lab injects generated speech into the emulator microphone and captures
the receiving emulator output. It never uses the computer's microphone. STOI is
an intelligibility estimate, not a MOS score, human listening result, or proof of
physical-device performance. Tests check the actual selected ICE candidate path.
Per-leg impairment settings must not be reported as end-to-end loss/latency.
Only completed, reproducible cases with valid source/capture signals count.
