CANCELLATION WHILE OUTGOING SETUP IS PENDING
Outgoing attempts now own their request UUID before contacting the server.
End Call updates the screen immediately and persists that ID even before a
CallRecord exists. Late server/native completions cannot bind or navigate the
cancelled attempt; a late native UUID is closed independently of any newer call.
An uncertain create response also queues cleanup, since a timeout does not prove
the server failed to create the call. A newer Firestore call state is preserved
instead of being overwritten by an older callable response.

The backend transaction records an end-before-create receipt under the caller's
own user record. startCall reads it in the creation transaction. Other users'
receipts cannot cancel a guessed request ID, and existing-call membership checks
still apply. Receipts are server-only, expire with the 90-day history retention,
and are removed by account deletion. A transactional deletion check prevents a
concurrent deletion from being followed by a new receipt. Deployment must include
the cancelledStarts TTL configuration; no production deployment was performed.

The outbox now processes an end intent added during an existing delivery. Its
previous single snapshot could leave that intent queued until another network
event. The controlled regression delivered only the first intent on the old code
and both intents with the fix. The final backend suite also verifies deletion of
cancellation receipts and denial of the deleted identity.

MEASUREMENT RULES
The audio lab injects generated speech into the emulator microphone and captures
the receiving emulator output. It never uses the computer's microphone. STOI is
an intelligibility estimate, not a MOS score, human listening result, or proof of
physical-device performance. Tests check the actual selected ICE candidate path.
Per-leg impairment settings must not be reported as end-to-end loss/latency.
Only completed, reproducible cases with valid source/capture signals count.
